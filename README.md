# Pre-meeting briefing agent

Give it a company or person and a meeting time. It returns a one-page brief on the **last 30 days**: what changed, open questions, conversation starters, and an explicit list of gaps. Every factual claim cites a numbered source, and claims that cannot be grounded are removed or flagged.

**Problem statement:** Pre-meeting briefing agent (founder sales-call prep, partnership research, investor briefings).
**Stack:** Tavily (live research). Node 18.18+, zero npm dependencies.

## Run it

```bash
# Configure and start the app
cp .env.example .env     # add TAVILY_API_KEY
npm start                # http://localhost:3000
npm test                 # grounding and window tests (no keys needed)
```
Deploy locally with Docker: `docker build -t briefing . && docker run -p 3000:3000 --env-file .env briefing`.

### Deploy to Render

Push this project to a GitHub repository and create a Render Web Service from
that repository. Set `TAVILY_API_KEY` in Render's environment settings.
Render uses the included Dockerfile and checks `/api/health`.

## Architecture

```
Browser UI ──POST /api/brief──▶ server.js ──▶ lib/brief.js
                                               │ 1. lib/research.js ──▶ Tavily  (4 angles + 1 general, parallel)
                                               │      dedupe, drop results dated outside [meeting-30d, min(now, meeting)]
                                               │ 2. number sources [S1..Sn]
                                               │ 3. offlineBrief(): source headlines/snippets into a concise brief
                                               └ 4. verify(): drop uncited claims, grounding check, auto-generated gaps
```

### How Tavily is used
- Company queries cover news, launches, hires/leadership, and partnerships/funding. Person queries cover role changes, announcements, and talks.
- `topic=news` with `days=30` plus one general search with `time_range=month`. Results are deduplicated, filtered to the window by `published_date`, and ranked by score.
- Undated results are kept but labelled as undated in the gaps section.

### Fully free mode
Live briefs use Tavily sources directly and do not require an LLM, Bifrost,
or a model provider key. The UI labels these as source-based briefs.

### Anti-hallucination design
1. The brief uses only the numbered sources and does not invent hires, launches, numbers, or personal details.
2. `verify()` **removes** any development with no valid source id.
3. A grounding check flags claims whose numbers or proper nouns do not appear in the cited text (shown as a "check this" tag).
4. Gaps are generated by code: undated sources, no hires or launches found, failed searches, and removed claims.
5. A meeting in the past or future sets the window end to `min(now, meeting)`.

## Evaluation
`npm test` runs 5 deterministic tests covering uncited claim removal, fabricated number/name detection, gap reporting, window filtering with dedupe, and JSON parsing. The grounding check is lexical, so it catches invented figures and names but not subtle misreadings. Click through the cited source for anything that matters.

## Limits and safety
- Only public web sources. No scraping of private profiles, and no personal details beyond what a source states. Treat person briefs as professional context only.
- Name collisions: use the "Disambiguate" field.
- Search coverage depends on what Tavily indexes. "Nothing found" does not mean nothing happened.

## Production hardening
- `lib/http.js`: 25s timeouts and exponential backoff on network errors, 429 and 5xx.
- A 10-minute response cache and a 10 requests/minute per-IP limit protect Tavily usage.
- Partial Tavily failures still produce a brief, with the failure listed under gaps.

## Demo without keys
`DEMO=1 npm start`, or click **Try a sample brief**. It uses a fictional company ("Northwind Robotics"), clearly labelled as a sample. It runs through the real `verify()`: one claim has no source and is removed, and one has a wrong figure and is flagged. Nothing in it is presented as real news.
